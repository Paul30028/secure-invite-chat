# 无手机号身份、多设备与恢复设计（设计稿）

> 状态：尚未实现。目标是在不使用手机号、通讯录或中心化明文恢复密钥的前提下，提供可理解的多设备和换机体验。

## 原则

- 一个“用户”由用户控制的根身份与已授权设备组成，不由手机号、广告 ID、邮箱或裸 deviceId 定义。
- 每台设备有独立不可导出的签名/密钥协商能力；设备私钥绝不从旧设备、服务端或备份中明文复制。
- 增加设备、恢复设备、吊销设备和修改恢复配置都是高风险操作，必须要求现有可信设备或用户持有的恢复材料确认。
- 服务端保存的是公开 credential、KeyPackage、设备状态和最小投递索引；不保存可还原的私钥、MLS group state 或聊天内容密钥。
- 用户可选择“不设恢复”。这会在所有设备和恢复材料丢失后永久失去历史会话访问；产品必须在设置时说清楚。

## 术语

| 名称 | 用途 | 可否离开设备 |
| --- | --- | --- |
| Root identity | 表示用户控制权的长期根公钥/策略 | 仅公开部分进入目录 |
| Device identity | 每台设备的签名身份与 MLS credential | 私钥不可导出 |
| Device agreement key | 接收配对/Welcome/恢复包 | 私钥不可导出 |
| Recovery secret | 用户离线保存的高熵恢复材料 | 仅由用户选择保存 |
| Encrypted recovery bundle | 经 recovery secret 保护的最小恢复状态 | 可存可选备份服务 |
| Push token | 不透明唤醒地址 | 独立于身份和群 ID |

## 首台设备注册

1. 首台设备在平台安全存储中生成 root identity 与 device identity；应用只得到公钥和受限签名能力。
2. 客户端生成可显示的用户标识（例如短公钥指纹/用户名证明），但不从昵称、时间或设备信息派生。
3. 向目录服务发布带 root 签名的设备 credential、MLS KeyPackage 和过期时间。
4. 客户端本地显示安全码与“恢复尚未配置”的状态。默认不上传任何可还原备份。
5. 目录的可审计证明用于发现服务端为不同客户端返回不同设备集合；它不是对聊天内容的访问权。

## 添加新设备

优先使用附近的已验证设备配对，而不是短信、邮箱或网页登录：

```
旧设备生成一次性配对请求 ─ QR / 本地安全通道 ─ 新设备
旧设备确认新设备安全码 ─ 加入授权签名 ─ 目录
旧设备按会话分别发送受保护的加入/恢复材料 ─ 新设备
```

- QR 只含一次性、短过期、绑定新设备公钥的配对会话；不是长期登录 token。
- 两端均显示彼此安全码与设备名称；用户必须在旧设备确认。
- 新设备生成自己的不可导出私钥，旧设备只授权其公钥，不迁移旧设备私钥。
- 对每个 MLS 群，现有成员设备经正常成员变更流程加入新设备；不得把旧 MLS state 文件直接复制给新设备。
- 新设备默认不自动获得历史明文。若产品提供历史迁移，必须从现有设备以会话级、端到端加密、用户可见的方式单独导入。

## 恢复

恢复材料采用用户控制的两层模式：

1. 生成至少 256 位高熵 Recovery Secret，并以二维码/恢复文件和可人工抄写的分段形式提示用户离线保存。
2. 可选的 Encrypted Recovery Bundle 只包含恢复策略、公开目录状态和重新授权所需的最小元数据；它以独立随机 bundle key 加密，bundle key 再由 Recovery Secret 包装。
3. 若用户选择口令辅助恢复，口令仅作为额外保护层，使用经审计的内存硬 KDF；不能把弱口令当作唯一密钥。
4. 备份服务仅按不透明 bundleId 保存密文，并实施删除、版本和速率限制；它不知道用户身份、Recovery Secret 或聊天密钥。
5. 恢复后生成**新设备**，再由 Root identity/Recovery Secret 授权其公钥。恢复不是取回旧设备私钥，也不自动恢复全部历史聊天明文。

恢复完成后，目录记录新设备和时间；所有现有设备收到安全事件。用户可在任何现有设备否决异常恢复并吊销该新设备。

## 设备吊销、丢失与重装

- 用户在任一可信设备或恢复流程中提交带 root 授权的 revoke；目录立即停止为被吊销设备发放 KeyPackage、推送或文件令牌。
- 各 MLS 群在获知吊销后执行成员移除 Commit；文件与通话密钥随 epoch/generation 轮换。
- 被吊销设备的本地副本、已下载附件和屏幕截图无法被远程抹除，UI 必须如实说明。
- 重装应用、安全硬件被清除、系统备份恢复到不同硬件时均视为新设备，不能用同一 deviceId 静默恢复。
- 服务端目录、推送注册和旧会话都设置过期与回收策略，避免已丢失设备长期保有投递能力。

## 隐私边界

- 设备名称、最后活跃时间、推送平台与 IP 可能构成元数据；默认只向本人设备和必要服务展示，避免在群成员列表公开。
- 新设备加入不应自动向所有历史联系人广播用户可识别的设备清单；只通知受影响会话所需的安全事件。
- 不上传通讯录，不用手机号匹配联系人；添加联系人依赖用户主动扫描、验证短码或导入用户明确选择的公开凭证。
- 崩溃报告和分析事件不包含 root 指纹、设备 credential、Recovery Secret、KeyPackage、群 ID 或 MLS state。

## 状态机与审计

```
uninitialized → active
active → pairing-pending → active
active → recovery-pending → active
active → revoked
recovery-pending → revoked
```

- 高风险状态变化产生本地不可伪造的安全事件记录，并在可用时向其他已授权设备同步。
- 目录响应包含 sequence 和透明性证明；客户端拒绝回滚到缺少已知设备撤销记录的视图。
- 用户可查看设备列表、最近授权/吊销操作、恢复状态与剩余恢复材料，但不显示或导出私钥。

## 验收门槛

- 无手机号、邮箱、通讯录或广告标识符的前提下完成首次注册、添加设备、丢机吊销与恢复。
- 配对 QR 重放、截屏、过期、换设备公钥、并发配对和目录回滚均被拒绝。
- 恢复 bundle 泄露、服务端泄露、弱口令、旧系统备份和单台设备失陷均不会导出原设备私钥或直接解密新消息。
- Android、iOS、桌面端分别证明安全存储、后台锁定、设备重装和系统备份行为符合本设计。
- 完成独立安全评审后才开放云端恢复；在此之前只提供用户离线恢复材料。
