# 网络隐私与可用性设计（设计稿）

> 状态：尚未实现。本设计提升网络在故障、封锁或单点服务不可用时的韧性；它不保证匿名、不保证绕过所有网络限制，也不能保护已失陷的设备。

## 威胁模型

| 对手/故障 | 可能看到或做到的事 | 本项目可缓解 | 不能承诺 |
| --- | --- | --- | --- |
| 本地网络/运营商 | 域名、IP、连接时间、流量大小；可阻断或限速 | TLS、替代中继、最小重连、可选代理 | 隐藏所有通信模式或保证可用 |
| 恶意中继/SFU/对象存储 | 客户端 IP、时序、密文大小与投递关系 | E2EE、密钥隔离、短期令牌、日志最小化 | 隐藏实时流量分析得到的元数据 |
| 服务端被入侵 | 密文、账户/设备注册元数据、短期会话状态 | 密钥不在服务端、分域、最小保留 | 保护服务端已保存的全部元数据 |
| 恶意群成员 | 保存明文、截图、转发、上传恶意内容 | 成员认证、移除、密钥 epoch、UI 告知 | 阻止已获授权成员复制内容 |
| 客户端被控/系统根证书被替换 | 明文、密钥使用、屏幕/键盘输入 | 平台安全存储、设备完整性提示 | 在被控设备上保护明文 |

产品文案必须区分“内容端到端加密”“隐藏对端 IP”“降低服务端关联能力”“网络可用性”。它们不是同一个属性。

## 传输分层

```
私聊/信令：客户端 ⇄ TLS/WSS 投递入口 ⇄ 密文服务
文件：客户端 ⇄ TLS 短期能力 URL ⇄ 密文对象存储
公告/目录：客户端 ⇄ 可选隐私中继 ⇄ 签名公告网关
通话：客户端 ⇄ TURN/SFU（受独立策略控制）
```

- **私聊投递**：生产环境仅允许 `wss://`，拒绝降级到 `ws://`；客户端固定最小 TLS 策略并进行正常证书校验。开发局域网模式必须有醒目的非生产标识。
- **文件**：对象 URL 不携带群 ID、文件名或可解密密钥；签名 URL 只作为短期传输授权。
- **公告**：公开通知可使用独立隐私中继，因为它是无状态拉取；OHTTP 适合降低“网关同时看到 IP 与请求内容”的关联，但不适合承载长连接实时聊天。
- **通话**：网络隐私优先模式强制 TURN relay；性能优先模式可尝试 P2P，但必须在建立前告知可能向对端暴露网络地址。

## 端点发现与防回滚

客户端不从未验证的网页、二维码或聊天消息中静默接受新的核心服务端点。端点目录采用签名 manifest：

```json
{
  "version": 1,
  "issuedAt": "2026-07-20T00:00:00Z",
  "expiresAt": "2026-08-20T00:00:00Z",
  "endpoints": [
    {"id": "relay-a", "url": "wss://relay-a.example", "role": "message-relay"},
    {"id": "notice-a", "url": "https://notice-a.example", "role": "public-notices"}
  ],
  "sequence": 81,
  "signature": "..."
}
```

- 根公钥随签名客户端发布；新 manifest 必须验签、检查过期、递增 sequence 和服务角色。
- 客户端缓存最近已验证目录；网络被阻断时可使用未过期缓存，不接受较旧目录回滚。
- 至少两个独立运营/地域的入口用于容灾，但客户端根据健康检查与用户选择切换，**不盲目并发连接全部入口**，避免扩大元数据暴露。
- 邀请串可包含用户手动确认的服务器地址，仅限演示/自托管模式；生产模式将其视为建议，展示域名与信任状态后要求确认。

## 会话与重连策略

- 每次网络连接使用新的认证 challenge 和短时会话；设备签名不作为长期 bearer token。
- 指数退避并加入安全随机抖动，设置上限与用户可见的“重新连接”入口；不无限快速重连造成特征化流量或电量消耗。
- 链接状态、错误码和失败次数可在本机保留；诊断上报默认关闭，开启时删除 URL 查询参数、设备 ID、候选 IP、密文与令牌。
- 中继切换后重新认证、重新同步并执行消息幂等去重；不得因为“可用性”跳过验签或接受旧 epoch。
- 发现 TLS/证书/签名异常时停止自动切换，提示用户检查网络和端点信任；不能自动降级到明文或未知证书。

## 元数据最小化

- 将公告、私聊投递、文件、通话和崩溃报告分到不同域名、凭证和日志管道；不使用全局广告/分析标识符。
- 中继日志默认只保留运行所需的聚合指标；IP、设备、群、时间的可关联日志需最短保留、访问审计和明确运维理由。
- 推送只发送不透明唤醒；唤醒后由客户端认证拉取。通知服务不获得私聊正文、联系人或群名。
- 对固定大小填充、批量发送、延迟投递等流量分析缓解措施先做成本与可用性评估；它们只能降低部分特征，不能保证匿名。

## 代理与受限网络

- 客户端可提供明确的“使用系统代理/用户配置代理”选项，并显示其影响：代理可见客户端 IP、目标域名和时序，但看不到 TLS 内的聊天内容。
- 私聊实时传输不把 OHTTP 当作通用隧道；公告拉取可在独立路径上评估 OHTTP。
- 任何备用传输都必须独立威胁建模、协议版本化、速率限制和安全审计。禁止把未审计的第三方代理、免费隧道或硬编码后门作为“抗封锁”功能。
- 当本地法律、组织规则或用户网络政策限制使用某种代理/中继时，客户端应尊重用户选择和部署者策略；产品不承诺规避所有限制。

## 运维安全

- TLS 证书、私钥、TURN 凭证根、公告签名根和服务端数据库密钥分别管理；轮换、吊销和访问审计独立进行。
- 入口服务使用最小权限、DDoS/滥用保护、地理与供应商冗余、可验证配置发布和定期恢复演练。
- 生产部署启用 HSTS、现代 TLS、证书自动续期与到期告警；变更需要双人复核和可回滚发布。
- 监控聚合于服务健康、延迟、错误率和容量，不采集消息内容或完整设备标识。

## 上线门槛

- 完成端点 manifest、签名轮换、回滚拒绝和离线缓存的测试向量。
- 对 TLS 错误、DNS 污染、入口阻断、服务端故障、证书误签、代理失效和网络迁移进行故障演练。
- 隐私评估公开说明每类组件看到的元数据、保留期和用户可选项。
- 独立安全审查确认不存在明文降级、未验证端点切换或把私聊标识泄露给公告/分析服务的路径。
