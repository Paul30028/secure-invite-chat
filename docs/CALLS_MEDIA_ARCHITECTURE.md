# 音视频通话架构（设计稿）

> 状态：尚未实现。WebRTC 的 DTLS-SRTP 保护浏览器与对端/中继之间的传输，但这本身不意味着 SFU 无法访问媒体。产品只有在编码帧额外端到端加密、密钥分发与成员变更均通过验证时，才可声明“端到端加密通话”。

## 分期范围

| 阶段 | 范围 | 媒体拓扑 | 对外安全表述 |
| --- | --- | --- | --- |
| C0 | 不上线通话 | 无 | 不适用 |
| C1 | 一对一语音/视频试验 | WebRTC P2P，必要时 TURN | 传输加密；不承诺隐藏 IP |
| C2 | 一对一正式通话 | 默认 TURN + 认证信令 | 仅在身份核验、密钥确认和安全存储完成后称为 E2EE |
| C3 | 小型群通话 | SFU 转发 | 只有启用并验证帧级 E2EE 时称为端到端媒体加密 |
| C4 | 大群通话 | SFU + 可选录制/直播隔离域 | 录制默认关闭；任何录制均明确提示且不与 E2EE 混称 |

初版不提供 SIP/PSTN 拨号、后台录音、云端转写、自动录制或服务端媒体分析。

## 组件与信任边界

```
已认证设备 A ─┐                    ┌─ 已认证设备 B
               │  加密信令（私聊投递） │
               ├──────────────────────┤
               │                      │
       TURN（可见 IP/时序/字节数）  SFU（可见媒体包元数据）
               │                      │
               └──── 编码帧 E2EE ────┘
```

- **信令服务**：只投递带会话 ID 的 offer、answer、ICE 候选和状态；不授予群成员外的设备加入权限。
- **STUN/TURN**：负责 NAT 穿透/中继。TURN 认证使用短期、单次会话凭证；日志最小化、严格保留期。隐私优先模式默认仅使用中继候选，代价是更高延迟和带宽成本。
- **SFU**：只转发加密编码帧；没有群 epoch、媒体密钥或可解密录制能力。SFU 认证与私聊投递服务分离。
- **客户端**：控制摄像头/麦克风权限、媒体帧加密、密钥轮换和安全码比对。私钥与群状态由安全存储保护。

## 通话与信令状态机

```
idle → incoming/outgoing → negotiating → key-confirming → connected → ending → ended
                         ↘ failed
```

### 一对一呼叫

1. 主叫生成 128 位随机 `callId` 和临时媒体会话上下文，向**已认证的指定设备**发送加密 `call_offer`。
2. 被叫显示来电 UI；仅在用户接受后请求摄像头/麦克风权限，并回传加密 `call_answer`。
3. 两端仅通过私聊加密信令投递 SDP/ICE。候选消息包含 `callId`、单调序号和签名/会话认证标签。
4. DTLS 建立后，双方从已认证的一对一会话导出 `media_root`；必须显示并允许人工比对安全码。
5. 连续加入的候选或 answer 必须匹配当前 callId、设备身份和状态机；乱序、重复、过期信令丢弃并审计。
6. 任一方挂断、网络切换、设备锁定或身份变化时吊销当前媒体密钥，清理本地帧缓冲和 TURN 凭证。

### 群组呼叫

1. 发起者向当前群 epoch 的已认证成员发布 `group_call_start`，其中含随机 `callId`、SFU 房间别名与成员版本。
2. 每个成员独立通过认证信令获得短期 SFU 接入令牌；令牌只绑定 callId、设备 ID、过期时间与最小权限。
3. 媒体帧密钥从当前群 epoch 派生，但另加 callId、发送者设备 ID、密钥代号和 ratchet 代数，不能与聊天/文件密钥直接复用。
4. 成员加入、离开、被移除或设备身份异常时，触发新的媒体代数；被移除成员立即失去新 SFU token 与新媒体密钥。
5. 客户端在成功安装新代数并验证成员版本前，不播放新代数媒体。

## 帧级端到端加密

客户端在编码器输出和 RTP 发送之间加密，在接收 RTP 与解码器输入之间解密。实现优先采用 W3C Encoded Transform/SFrame 兼容能力，不自行发明裸帧格式。

每个加密帧至少绑定：

```text
protocolVersion | callId | senderDeviceId | mediaKind | keyId |
generation | frameCounter | codecMetadata
```

- 使用 AEAD；nonce 由每个发送者、每个 keyId、每个媒体方向的单调 frameCounter 唯一构造，绝不从时间或 `Math.random` 派生。
- 视频关键帧处理、重传、带宽自适应与 simulcast 必须在真实设备矩阵中验证，不能只靠模拟器。
- `keyId` 和 generation 可暴露给 SFU 用于转发，但不得暴露媒体内容或群密钥。
- 任何一端不支持帧级 E2EE、无法安全存储媒体密钥或安全码未确认时，默认不接入“私密通话”；UI 明确说明降级原因，禁止静默降级。

## 权限、隐私与 UX

- 摄像头/麦克风权限仅在用户明确操作后请求；前台显示麦克风/摄像头状态和当前设备。
- 不自动打开摄像头；接听语音来电时也不打开视频。
- 默认禁用屏幕共享；启用时选择窗口/屏幕并显示持续提示。屏幕共享不等于防截屏。
- 通话记录默认仅保存在本机的最小化状态（开始/结束/未接），不记录媒体内容。
- IP、时序、在线状态和群规模可能仍暴露给 TURN/SFU/网络运营商；隐私模式可强制 TURN，但不能承诺匿名或不可审查。

## 防滥用与韧性

- 呼叫邀请按联系人/群和设备限速；拒绝未知设备的自动响铃。
- 信令请求有大小上限、schema 校验、callId 绑定与短过期时间；不允许任意 JSON 转发。
- TURN 凭证 TTL 不超过通话窗口；结束、踢出或身份变更即时撤销。
- SFU 使用独立项目/租户、最小日志、监控告警和带宽配额，不能访问私聊数据库。
- 失败时客户端只显示必要的错误；诊断日志不得写入 SDP 中的私网候选、媒体密钥或完整 token。

## 验收门槛

- 两端设备身份认证、安全存储和一对一密钥协议先于正式一对一通话完成。
- 具备多浏览器/Android/iOS/Tauri 互操作矩阵；不支持的环境明确拒绝而非降级。
- 对信令重放、候选注入、token 复用、成员被移除、网络迁移、设备锁定、丢包与密钥轮换有自动化测试。
- 群通话在独立安全评审确认 SFU 无法解密媒体、密钥轮换正确且无静默降级后才发布。
- 完成 TURN/SFU 供应商、日志保留、地域、容量与滥用响应的隐私和运维评审。
