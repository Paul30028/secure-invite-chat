# 安全验证与测试矩阵

> 本计划把安全架构中的声明变成可验证的发布条件。通过测试不等于完成安全审计；测试失败或覆盖缺失时，功能不得被描述为已具备对应安全属性。

## 分层策略

| 层级 | 目的 | 执行频率 | 阻止发布 |
| --- | --- | --- | --- |
| 单元测试 | 固定编码、签名、随机数、状态机和边界条件 | 每次提交 | 是 |
| 协议测试向量 | 多语言/多平台对相同输入得到相同安全结果 | 每次 Core 变更 | 是 |
| 集成测试 | 客户端、目录、中继、文件、推送和存储协作 | 每次合并/候选版本 | 是 |
| 端到端测试 | 真实设备上的关键用户旅程 | 每个候选版本 | 是 |
| 模糊/属性测试 | 发现解析、状态、并发和异常输入问题 | 定期及发布前 | 是 |
| 渗透与审计 | 独立验证架构与实现假设 | 重要发布前 | 是 |
| 故障演练 | 证书、端点、密钥、服务和网络故障响应 | 季度/发布前 | 是 |

CI 当前构建、Python 语法检查和服务端单元测试是第一层的起点；发布流程必须逐步覆盖后续层。

## 必测安全属性

### 设备认证与目录

| 属性 | 自动验证 | 人工/独立验证 |
| --- | --- | --- |
| 挑战签名绑定连接、动作、群和设备 | 有效、篡改、过期、跨连接、跨群、跨设备测试向量 | 协议审查 |
| 私钥不落入 WebView 常规存储 | Android/iOS/Tauri 存储扫描、迁移/重启测试 | 平台安全存储检查 |
| KeyPackage 与设备 credential 一致 | 目录 proof、替换/过期/撤销测试 | 透明性日志审计 |
| 目录不分叉/不回滚 | inclusion、non-inclusion、consistency、错误 witness 测试 | 独立 monitor 演练 |
| 配对和恢复不可重放 | QR 过期、设备公钥改变、并发配对、恢复撤销测试 | 交互安全评审 |

### MLS 会话

| 属性 | 自动验证 | 人工/独立验证 |
| --- | --- | --- |
| 新成员正确接收 Welcome | 固定 MLS 向量、跨平台互操作 | Core 实现审计 |
| 移除成员后无法解密新消息 | Add/Remove Commit 与新 epoch 测试 | 密钥状态检查 |
| 篡改、重放、乱序和 fork 被隔离 | 属性/模糊测试与状态机测试 | 攻击路径审查 |
| 离线恢复不复用 nonce 或旧 state | 崩溃恢复、数据库回滚、双设备并发测试 | 安全存储审计 |
| 文件/通话密钥域隔离 | exporter label、context、generation 测试 | 密钥派生审查 |

### 消息、文件与链接

| 属性 | 自动验证 | 人工/独立验证 |
| --- | --- | --- |
| 验签失败内容不渲染 | 消息篡改、TOFU 污染、文件元数据伪造测试 | UI 隔离检查 |
| 服务端输入不进入危险分支 | schema、极大字段、控制字符、未知字段、速率测试 | 代码审查 |
| 分块文件完整性 | 每块 AAD、hash、缺块、错误顺序、续传测试 | 大文件和断网设备测试 |
| 撤回和过期不作过度承诺 | 已下载副本、对象删除、令牌到期测试 | UX 文案评审 |
| 外链不自动泄露 | 网络拦截测试：聊天渲染/通知/缓存无请求 | 隐私评审 |

### 公告、网络与通话

| 属性 | 自动验证 | 人工/独立验证 |
| --- | --- | --- |
| 公告必须可信发布者签名 | key rotation、撤回、sequence 回退和篡改测试 | 发布者密钥审计 |
| 推送没有私聊内容 | payload schema 与抓包断言 | 平台推送配置审计 |
| 端点目录无降级/回滚 | manifest 签名、过期、DNS/证书失败测试 | 故障演练 |
| 一对一通话信令受认证保护 | callId、重放、候选注入、token 过期测试 | WebRTC 安全评审 |
| 群媒体 E2EE 无静默降级 | 编码帧 transform、成员变化、能力不支持测试 | SFU 黑盒测试 |

## 测试数据与日志规则

- 测试向量使用专用、固定、非生产密钥；生产私钥、Recovery Secret、真实群状态和真实文件禁止进入仓库、CI artifact 或测试日志。
- CI artifact 默认只保存失败所需的最小日志，并对 URL、token、IP、设备 credential、密文和文件名做脱敏。
- 安全回归测试以缺陷编号、影响属性、最小复现输入和修复版本关联；不在公开日志放出可被滥用的生产细节。
- 任何需要真实设备或第三方服务的测试均使用独立测试租户、测试域名和短期凭证。

## 发布验收清单

### Alpha（内部）

- 客户端构建、服务端测试、协议单元测试和静态检查全绿。
- 所有显著安全限制显示在 UI/文档中。
- 无生产秘密、真实密钥或个人数据进入仓库和 CI。
- 新功能有最少一条成功、一条篡改/失败、一条恢复/撤销测试。

### Beta（受控外测）

- 安全存储、MLS、目录、文件和网络路径的跨端端到端测试通过。
- 依赖 SBOM、签名候选产物、来源证明和漏洞扫描可用。
- 至少一次丢机吊销、目录异常、端点故障、升级回滚和服务恢复演练完成。
- 安全问题报告渠道和响应负责人已指定。

### 正式公开

- 独立密码学审计、应用渗透测试、隐私评估和供应链评审完成并处理阻塞问题。
- 可验证发布/更新、撤回、密钥轮换和事故公告已演练。
- 宣传文案逐条对应已通过的属性；剩余元数据、终端和网络风险清楚披露。
- 对每一个“端到端加密”“设备已验证”“媒体 E2EE”“隐私模式”标签，均有自动化回归测试和人工证据。

## 缺陷分级与处置

- P0：可导致未授权解密、私钥导出、远程代码执行、更新签名绕过或大规模身份替换。停止发布，立即缓解与通知。
- P1：可绕过成员移除、泄露敏感元数据、破坏核心身份验证或造成持续拒绝服务。阻止正式发布，优先修复。
- P2：需特定前提的边界绕过、明显隐私 UX 缺陷或重要可靠性问题。修复后进入受控验证。
- P3：不影响安全边界的体验、文档或低风险稳健性问题。记录、排期并回归。

每个安全缺陷关闭前需包含根因、修复、回归测试、受影响版本、是否需要密钥/端点/发布物轮换，以及用户沟通结论。
