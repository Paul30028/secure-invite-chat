# 发布、更新与供应链安全（设计稿）

> 状态：尚未实现。客户端代码本身是端到端加密威胁模型的一部分；若攻击者能替换安装包、热更新、依赖或构建环境，就能在加密前读取明文。

## 安全目标

- 用户可验证桌面、Android、iOS、服务端镜像和公开文档来自预期发布流程。
- 每个发布物可追溯到受保护分支、精确提交、锁定依赖和受控构建环境。
- 自动更新只能安装已验证、未回滚、与目标平台/架构匹配的版本。
- 发布签名密钥、商店凭证、通知签名根和生产部署凭证相互隔离。
- 漏洞响应、紧急撤回和安全公告不依赖非官方社交账号或可被篡改的网页。

## 构建与依赖策略

| 层 | 正式要求 |
| --- | --- |
| 源码 | 受保护主分支、强制审查、签名提交或受控合并、最小写入权限 |
| JavaScript | 提交锁文件；CI 使用 npm ci；新依赖须许可证、维护状态和漏洞评估 |
| Rust/Android/iOS | 锁定依赖/工具链；Native 与 FFI 版本与加密 Core 版本绑定 |
| CI | 最小权限、短期 OIDC 凭证、固定 action 版本或受控更新策略、隔离秘密 |
| 构建产物 | 生成 SHA-256、SBOM、测试结果和 provenance；不从开发者电脑手工上传 |
| 部署镜像 | 固定 digest、扫描、签名、部署前验证；运行时最小权限 |

当前 CI 的构建检查只是起点。发布流水线要与普通 pull request 流水线分开：PR 不应接触签名、商店、生产或发布密钥。

## 签名与来源证明

每个正式 release 产生以下并一起发布：

~~~
artifact
artifact.sha256
artifact.signature / platform-native signature
provenance.intoto.jsonl
sbom.spdx.json
release-manifest.json
~~~

Release manifest 至少包含版本、提交 SHA、构建平台、目标架构、产物 hash、最低可升级版本、发布时间、撤回状态与签名。

- Android 使用受保护的应用签名方案；上传密钥与发布密钥分离，并有离线/硬件备份与轮换流程。
- iOS 使用 Apple 的受控签名与发布渠道；证书/配置文件不进入源码或普通 CI 日志。
- Windows/macOS/Linux 采用平台原生签名和可验证的独立 release manifest；客户端安装/更新时同时验证平台签名和 manifest 签名。
- 服务端容器/二进制使用可验证签名与 digest 部署；生产节点只拉取被策略允许的发布者、仓库和工作流来源。
- 可使用 Sigstore 的身份绑定签名与透明日志辅助审计，但它不替代平台商店签名、发布审批或密钥轮换策略。

## 自动更新

1. 客户端向固定或透明更新目录拉取签名 update manifest。
2. 校验目录/manifest 签名、目标平台、版本单调性、发布时间窗口与产物 hash。
3. 下载产物后校验 hash 和平台签名；失败即删除下载并报告可理解错误。
4. 安装前保留当前可用版本；升级后执行健康检查，失败可回滚到已验证旧版本。
5. 安全紧急撤回由多签/阈值发布者签名，客户端显示撤回原因和可用替代版本。

禁止通过聊天消息、公告正文、未签名网页 JSON、远程脚本或任意 URL 触发应用更新。桌面端不加载可执行“热更新”代码；静态内容更新也必须有内容签名与严格域隔离。

## 密钥管理与职责分离

- 发布批准人、构建维护人、基础设施运维、公告发布人和事故响应人使用独立身份与最小权限。
- 长期根密钥离线或硬件保护；日常签名使用受限、可轮换子密钥或短期身份凭证。
- 任何单一 CI token 都不能同时修改源码、签名产物、发布 manifest 和生产部署。
- 每次签名、发布、撤回、密钥轮换和权限变更写入审计日志；日志不可包含私聊内容、恢复材料或生产秘密。
- 所有密钥泄露预案包含：停止发布、撤销/轮换、客户端拒绝规则、用户通知、取证保全和复盘。

## 漏洞管理

- 建立安全报告渠道、响应目标、CVE/公告策略和保密修复窗口；不要求报告者公开敏感细节。
- 每次依赖更新执行漏洞扫描、许可证扫描和必要的人工评估；加密库、FFI、WebView、Tauri/Capacitor 插件和 WebRTC 依赖列为高优先级。
- 对严重客户端漏洞，发布签名安全公告和最小化强制升级策略；强制升级不能把用户锁定到未验证或不可访问的下载源。
- 事故报告公开影响范围、缓解措施、版本和剩余风险，避免声称“没有影响”而缺乏证据。

## 发布门槛

- 所有平台产物都可由独立环境复核来源、hash、签名和 SBOM。
- 自动更新、回滚保护、撤回、断网恢复、证书过期、签名密钥轮换和镜像污染均有测试。
- CI 供应链与权限设置完成审计；PR 工作流不具备发布能力。
- 至少完成一次端到端演练：从受保护提交到签名发布、客户端验证、紧急撤回与安全公告。
- 遵循风险导向的安全开发框架，形成可审计的威胁建模、代码审查、测试、发布与漏洞响应记录。
