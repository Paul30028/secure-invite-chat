# 产品 MVP 与交付路线

> 本文把安全架构转化为产品范围。它不改变任何密码学结论：原型在 MLS、安全存储、多设备与独立审计完成前，不能宣传为 Signal 级安全产品。

## 产品定位

一个无需手机号、邀请制的私密通信应用：

- 私聊与群聊：端到端加密、设备身份可验证。
- 文件与链接：文件端到端加密；外链不自动泄露阅读行为。
- 通话：先一对一、后群通话；媒体端到端加密有明确前置条件。
- 首页公告：公开且签名验证，与私聊完全隔离。
- 隐私与韧性：减少不必要元数据、支持可信端点切换，但不承诺匿名或永不受网络限制影响。

## 用户角色

| 角色 | 核心需求 | 不能拥有的能力 |
| --- | --- | --- |
| 普通成员 | 加入、聊天、发送文件、核验设备、离开 | 解密他人会话、读取服务器明文、管理无关成员 |
| 群管理员 | 创建群、批准邀请、移除成员、发起迁移 | 读取成员私钥、伪造成员消息、绕过 MLS 成员变更 |
| 公告发布者 | 发布已签名公开通知 | 访问私聊、定位公告读者、给客户端执行脚本 |
| 运维人员 | 保持投递/存储/中继可用 | 解密内容、生成用户设备私钥、替用户签名 |
| 安全响应人员 | 审计、撤回发布物、处置漏洞 | 读取聊天内容或恢复材料 |

## 第一版信息架构

~~~
首页
 ├─ 已验证的公开公告
 ├─ 私密会话列表
 └─ 连接/安全状态入口
会话
 ├─ 消息、文件、受限链接
 ├─ 成员与安全码
 └─ 通话入口（符合版本能力时）
新建
 ├─ 创建私密群
 ├─ 扫描/粘贴邀请
 └─ 添加联系人/设备（主动凭证）
设置
 ├─ 设备与恢复
 ├─ 网络与代理
 ├─ 存储与隐私
 └─ 安全状态/版本
~~~

首页的公告卡片必须明确标注“公开公告”，颜色、图标与私聊消息区分；公告阅读、订阅和私聊身份不共用标识符。

## 分阶段交付

### P0：原型安全收口

目标：阻止原型被误当成生产安全产品，并让已有演示更稳健。

- 完成输入 schema、消息验签隔离、设备挑战认证、大小限制和基础测试。
- 关闭生产环境 local debug、LAN 地址泄露和明文 WS 降级路径。
- 在 UI 和 README 标注旧共享群密钥、localStorage 与无前向保密的限制。
- 输出并维护本仓库中的威胁模型、协议 ADR 和发布门槛。

**退出条件**：原型可演示，但发布页面不使用“Signal 级”“完全匿名”“无法审查”等表述。

### P1：可信设备基础

目标：让“谁在和谁通信”可验证，且私钥离开 WebView 存储。

- 实现移动/桌面 SecureKeyStore、加密状态库与一次性旧数据迁移。
- 落地无手机号设备注册、短期 QR 配对、丢机吊销和离线恢复材料。
- 将挑战认证强制开启；移除裸 deviceId 恢复会话路径。
- 引入设备目录的签名 checkpoint 与客户端验证界面。

**退出条件**：新生产设备没有敏感密钥落在 localStorage；异常设备变化会阻断敏感操作并可由用户核验。

### P2：MLS 私密消息

目标：新会话具备可审计的成员变更与现代群密钥状态。

- 完成 Rust MLS Core 的跨平台 PoC、测试向量和许可证/供应链审查。
- 部署 KeyPackage、Welcome、Commit 和透明性目录最小服务。
- 新建一对一/群会话只使用 MLS；旧会话只读并提供显式迁移。
- 建立多设备、乱序消息、离线恢复、成员移除和状态冲突测试。

**退出条件**：移除成员会产生可验证的新 epoch；旧成员无法解密后续新消息。

### P3：文件、通知与可用性

目标：完成日常通信能力，但不牺牲隐私边界。

- 分块加密文件、短期能力令牌、续传、过期和撤回提示。
- 签名公告目录、客户端验签、公开内容缓存与不透明推送唤醒。
- 签名端点目录、网络健康检查、用户代理设置和最小化诊断。
- 链接默认文本显示，预览为显式可选功能。

**退出条件**：文件服务无法解密文件；公告源与私聊投递/身份隔离；没有后台外链抓取。

### P4：通话与公开发布

目标：先稳健一对一通话，再评估群通话。

- 一对一 WebRTC、认证信令、短期 TURN 凭证、身份安全码和媒体密钥导出。
- 在平台能力矩阵满足时启用编码帧级 E2EE；不支持的客户端明确拒绝私密通话。
- 群通话引入 SFU 前完成独立安全评审、带宽/滥用设计和成员变更密钥轮换。
- 完成签名发布、SBOM、来源证明、独立审计、渗透测试与漏洞响应演练。

**退出条件**：对外发布的每个平台版本可验证来源；安全能力表与实际实现一致。

## 关键用户旅程

### 创建和邀请

1. 用户首次打开应用，创建本机设备身份并看到恢复提示。
2. 创建群时客户端生成 MLS 会话；管理员分享一次性、可验证邀请。
3. 成员扫码或粘贴邀请，客户端展示群/管理员凭证与安全状态。
4. 成员加入成功后，所有参与设备完成 MLS 变更；管理员可在成员页核验和移除设备。

### 换机和丢机

1. 有旧设备：扫描短期 QR，双方确认安全码；新机生成自己的私钥。
2. 无旧设备：使用离线 Recovery Secret 创建新设备，向其他设备显示恢复安全事件。
3. 丢失设备：用户吊销它；会话执行成员移除和密钥轮换。
4. 任何恢复或配对异常都不静默接受，用户可取消并通过独立渠道核验。

### 公告

1. 客户端拉取签名公告，验证发布者目录和内容签名。
2. 验证通过才在首页展示；验签失败只显示安全状态，不显示正文。
3. 推送只是“有更新”唤醒；内容由客户端拉取验证。
4. 公告链接必须由用户点击，不能触发隐藏请求或与私聊身份关联。

## 明确延后/拒绝的能力

- 手机号/通讯录匹配、广告追踪、消息内容分析、云端明文备份。
- “已读回执”“输入中”默认开启；若提供必须是会话级可选且受 E2EE 信令保护。
- 后台自动链接预览、服务端病毒扫描 E2EE 文件、无提示云端录制/转写。
- 将普通 Web 端宣称为高风险正式安全客户端。
- 未审计的自研群双棘轮、密钥恢复、匿名路由或反封锁隧道。

## 产品指标

上线后只采集不关联私聊身份的最小化健康指标：

- 本地成功/失败的建群、入群、密钥同步与恢复比例。
- 中继连接成功率、延迟、文件传输完整率和通话质量的聚合数据。
- 已验证公告拉取成功率、更新验证失败数和客户端版本分布。

不采集消息正文、文件名/哈希、联系人、群成员、完整设备标识、Recovery Secret、MLS state 或精确可追踪的阅读行为。
