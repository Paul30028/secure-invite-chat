# 私密文件与链接协议（设计稿）

> 状态：尚未实现。当前原型把整个小文件装入聊天密文并经 WebSocket 转发，适合演示，不具备大文件、断点续传、撤回、独立密钥或可靠清理能力。

## 目标

- 每个文件使用独立内容密钥；群/会话密钥仅用于保护该内容密钥。
- 对象存储、CDN 与中继只能获得密文分块、有限大小信息和短期上传/下载能力。
- 客户端验证每个分块及完整文件的完整性，支持安全的暂停与续传。
- 外部链接不自动请求，不让服务器替用户无提示抓取，避免泄露读者 IP、群关系或阅读行为。

## 文件对象模型

```
聊天消息（当前群 epoch 加密）
  └─ FileDescriptor
      ├─ fileId、epoch、算法版本
      ├─ 加密的 fileKey package
      ├─ manifestHash、总大小、分块大小、过期时间
      └─ opaque object prefix
对象存储
  ├─ encrypted manifest
  └─ encrypted chunks: <fileId>/<chunkIndex>
```

`fileId` 使用 128 位以上安全随机值，不能从文件名、内容哈希、群 ID 或时间生成。服务端对象路径只使用 fileId 与固定分块序号；路径中不出现用户、群、原文件名或 MIME 类型。

## 加密格式

### 1. 内容密钥与分块

1. 客户端生成 256 位随机 `fileKey` 和 `fileId`。
2. 文件以固定 `chunkSize`（例如 1 MiB，版本化）读取；不把整个文件载入内存。
3. 每块用 AEAD 加密；每块 nonce 必须对 `fileKey` 唯一。
4. 关联数据（AAD）固定编码为：

```text
protocolVersion | fileId | chunkIndex | plainLength | totalChunks | epoch
```

5. 每块密文计算 hash；所有 hash、大小和顺序写入 manifest。manifest 也用 `fileKey` 加密并认证。
6. 客户端以当前群 epoch 或成熟群协议的 exporter secret 包装 `fileKey`，形成只对当前成员可解的 `fileKeyPackage`。

绝不从群密钥直接加密全部文件，也不复用聊天消息的 nonce。文件名、MIME、缩略图和总大小应视为敏感元数据，放在加密 manifest 或加密 descriptor 中。

### 2. 描述符

```json
{
  "version": 1,
  "fileId": "base64url-random-id",
  "epoch": 12,
  "objectPrefix": "v1/f/<opaque-file-id>",
  "manifestHash": "base64url",
  "cipherSuite": "AES-256-GCM",
  "chunkSize": 1048576,
  "totalChunks": 37,
  "expiresAt": "2026-08-20T00:00:00Z",
  "fileKeyPackage": "base64url",
  "signatureOrSenderAuth": "…"
}
```

描述符作为聊天消息的内容，受当前消息认证、重放保护和发送者身份验证保护。对象路径只是能力定位符，不构成读取授权。

## 上传与下载授权

- 客户端先向文件服务请求与 `fileId`、chunk 范围、操作类型、过期时间绑定的**短期单用途**能力令牌。
- 文件服务确认客户端是经认证的当前群成员，但不接收 fileKey、文件名或明文 hash。
- 上传和下载令牌不可跨 fileId、群 epoch、设备或操作复用；令牌不写入日志、崩溃报告或聊天消息。
- 客户端直传对象存储时，预签名 URL 的 TTL 极短，方法、内容长度、对象路径和 hash 均受约束。
- 成员被移除后，文件服务拒绝续发新令牌；已拿到的密文可能仍被旧成员保存，因此 UI 必须诚实说明“撤回不能收回已下载内容”。

## 完整性、续传与恢复

- 下载前先取得并解密 manifest，验证其 hash 与 descriptor 一致；随后逐块校验 AEAD 和 hash。
- 本地只保存加密的下载进度：fileId、已验证 chunk 位图、加密 manifest 状态；不存 fileKey 明文。
- 重试仅请求失败块；超过限制后显示明确损坏提示，不能把未验证内容交给预览器或系统打开。
- 文件最终写入用户可见目录前，先完成完整验证；名称做安全规范化，拒绝路径穿越、控制字符和危险扩展名伪装。
- 可选病毒扫描只允许对**用户明确上传的本地明文**在客户端完成；服务端无法扫描 E2EE 文件，不能对此作出保证。

## 过期、撤回与保留

- 文件服务按 `expiresAt` 删除密文对象和未完成上传；删除任务可审计但不记录密钥。
- `revoke` 消息使客户端不再提供下载入口，并请求删除服务端尚存密文；它不是对历史下载副本的密码学擦除。
- 后续群 epoch 不会自动使历史文件不可解：若需要前向保密或移除后的内容控制，必须依赖成熟群协议和新文件密钥分发策略。
- 默认保留期应短且用户可见；法律保留、备份、CDN 边缘缓存和灾备副本必须单独披露。

## 链接与预览隐私

- 聊天中链接只作为加密消息正文的一部分；客户端渲染为文本，用户点击后才打开。
- 默认关闭远端预览、favicon 抓取、URL 安全扫描和自动展开，因为这些行为会向第三方泄露 URL、客户端 IP 和访问时机。
- 用户显式开启预览时，优先在客户端的隔离请求上下文中抓取；展示即将访问的域名、请求的隐私影响和关闭选项。
- 不建立“服务端 URL 抓取代理”作为默认功能。若未来提供，必须单独同意、去除聊天身份、设定严格网络出口/SSRF 防护、缓存隔离和短保留期。
- 禁止执行远端页面脚本；只允许经净化的标题、描述和静态缩略图，且这些数据也必须作为聊天密文发送。

## 当前原型的迁移路径

1. 保留 ≤4 MiB 的 WebSocket 内嵌文件为显式“演示模式”，在 UI 中标明限制。
2. 新增客户端流式分块加密与 FileDescriptor；先用测试对象存储环境验证互操作。
3. 文件服务只实现认证、短期能力令牌、对象删除与配额，不接收密钥。
4. 完成成员变更 epoch、安全存储和设备认证后，才为生产群开放下载令牌。
5. 建立断点续传、损坏分块、令牌重放、撤回、过期和跨端互操作测试向量。

## 发布门槛

- 大小、分块计数、manifest、AAD、nonce 和 hash 具备固定测试向量。
- iOS、Android、桌面端在大文件、后台切换、网络中断和磁盘不足时不泄露 key 或未验证明文。
- 对象存储策略、CDN、预签名 URL、日志、备份和删除作业通过隐私与渗透测试。
- 链接预览默认关闭并有端到端测试，确保没有后台请求。
