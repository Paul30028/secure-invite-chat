# 音视频通话测试与部署

## 已实现的功能

- 一对一语音通话与视频通话
- 选择在线群成员后发起呼叫
- 来电接听、拒绝、挂断、45 秒无人接听超时
- 麦克风静音、摄像头开关、前后摄像头切换
- WebSocket 服务仅转发 WebRTC 的呼叫信令；媒体流不经过本项目服务器

当前不提供多人群视频会议。群成员选择器发起的是一对一通话。

## 两台电脑的本地测试

1. 在同一台电脑启动中继：

```powershell
python server/server.py
```

2. 用两台电脑或两个独立浏览器配置文件，连接同一个中继，创建并加入同一群。
3. 两端都打开该群，确认成员列表显示为在线。
4. 聊天顶部点击电话或视频图标，选择在线成员。
5. 被呼叫端点击“接听”，并允许浏览器使用麦克风/摄像头。
6. 测试语音、视频、静音、关闭摄像头、翻转摄像头与挂断。

电脑本机的 `http://localhost` 是浏览器认可的安全上下文，可以请求媒体权限。

## 手机测试的必要条件

手机浏览器通常只允许在 **HTTPS 页面** 上使用摄像头和麦克风。

- 文字、链接、文件可用局域网 `ws://电脑IP:8765` 测试。
- 手机音视频需将前端部署到 `https://`，并把中继通过 TLS 反向代理为 `wss://`。
- 手机和电脑使用同一域名时，应把 App 的 WebSocket 地址设置为对应的 `wss://` 地址。

项目已有 WSS 部署文档：`docs/DEPLOY_WSS.md`。

## 跨网络通话

同一局域网优先使用设备直连候选。不同网络、蜂窝网络或受限路由器环境还需要 TURN 中继。

部署时应提供可用的 TURN 地址、用户名和临时凭据；在此配置完成前，跨网络音视频不应承诺可用。TURN 凭据管理、呼叫身份验证和端到端安全审计属于后续安全阶段。

## 安全边界

WebRTC 媒体传输使用浏览器的 DTLS-SRTP 通道，但这不等同于 Signal 的端到端安全保证。本原型尚未完成呼叫身份验证、密钥确认、TURN 凭据轮换和安全审计，不应用于高风险通信。
