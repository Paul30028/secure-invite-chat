# 邀群密聊 × Signal 式安全对照

## 你在用手机时：Wi‑Fi 还是流量？

| 场景 | 中继怎么部署 | App 设置里填什么 |
|------|----------------|------------------|
| 同一 Wi‑Fi 小团队 | 电脑/NAS 跑 `server.py` | `ws://192.168.x.x:8765` |
| 手机流量 / 不在一起 | **公网 VPS + 域名 + HTTPS/WSS** | `wss://chat.你的域名.com` |
| 仅演示本机 | `127.0.0.1` | 手机访问不到本机环回 |

要点：

1. **端到端加密（E2EE）**：即使走明文 `ws://` 被同网窃听，攻击者也只能看到密文；但会暴露「谁、何时、消息多长」。
2. **传输层加密（TLS/WSS）**：手机流量场景必须上，防运营商/中间人改包、注入、窥探元数据。Signal 客户端到服务器也是 TLS。
3. 自托管没有 Signal 的全球 CDN；你要自己保证服务器在线与证书有效。

## 已实现的 Signal 风格措施

| 措施 | 我们做的 | Signal 对比 |
|------|----------|-------------|
| 端到端加密 | AES-256-GCM，密钥仅客户端 | Signal Protocol（更强前向保密） |
| 服务器不见明文 | 只存 ciphertext + iv | 同 |
| 无全局通讯录 | 仅邀请串入群 | 有电话号码身份（我们更「封闭」） |
| 邀请凭证高强度随机 | `secrets` / 高强度 token | 群链接类似 |
| 密钥与入群码分离 | SIC1.入群码.群密钥材料 | 入群与会话密钥分层 |
| **设备身份签名** | ECDSA P-256 签消息内容（TOFU） | 身份密钥 + 安全号码 |
| **群安全码** | SHA 派生 60 位数字，可线下核对 | Safety Number |
| **签名/密钥变更警告** | UI 标红 + 顶部警报 | 类似密钥变更提示 |
| **元数据收缩** | 昵称进密文信封，服务器侧写 `e2ee` | Sealed Sender 更强 |
| **长度填充** | 随机 pad 字段 | 有填充策略 |
| 历史密文拉取 | 服务端只回放密文 | 多设备同步更复杂 |

## 尚未达到 Signal 的部分（诚实）

| 缺口 | 风险 | 后续 |
|------|------|------|
| 无 Double Ratchet / 前向保密 | 群密钥泄露 → 历史可解 | Phase 5 大工程 |
| 无 Sealed Sender | 服务器仍知 device_id 与时间 | 混淆层 / 代理 |
| TOFU 非完整信任网络 | 首次公钥可被中继时的假冒（若同时无安全码核对） | 强制核对安全码 |
| 文件走 WS 单帧 | 大文件与流量特征 | 分片 + 对象存储密文 |
| 无封闭来源 / 可重放 | 需服务端幂等与客户端去重（已有 id 去重） | 扩展 |

**实用建议**：小团队互信 + 自托管时，**务必线下核对一次群安全码**，并尽量使用 **WSS**。

## Android 额外防护

- 打包脚本写入 `FLAG_SECURE` 可选说明（防截屏进多任务预览，见 `docs/ANDROID_APK.md`）
- 生产构建应使用 `wss://`，并收紧 `network_security_config`（禁止明文流量）
