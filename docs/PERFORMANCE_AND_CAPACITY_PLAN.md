# 性能、容量与可靠性设计

> 状态：尚未实现。此文档定义容量规划和压测原则；具体 SLO、阈值和部署规模需基于真实目标地区、用户量、网络条件与成本模型设定。

## 服务分域

| 域 | 工作负载 | 主要瓶颈 | 不应拥有 |
| --- | --- | --- | --- |
| 消息中继 | 长连接、密文扇出、短期离线队列 | 连接数、内存、出站带宽、队列背压 | 解密密钥、正文索引 |
| 目录 | credential、KeyPackage、proof、checkpoint | 写入序列、Merkle 计算、proof 读取 | 私聊内容、群成员明文 |
| 文件 | 加密对象上传/下载、TTL 清理 | 对象带宽、存储、并发分块、CDN | fileKey、文件名明文 |
| 公告 | 签名内容分发、缓存、验证 | CDN 缓存、发布审核 | 私聊身份、读者画像 |
| 推送 | 不透明唤醒队列 | 平台配额、重试、失效 token | 消息正文、群名 |
| TURN/SFU | 实时包转发 | 网络带宽、端口、CPU、地域延迟 | 媒体解密密钥 |

这些域独立扩缩容、凭证、日志、网络策略和故障预算，避免一个热门公告、文件上传或通话峰值拖垮私聊投递。

## 中继设计

- 连接层与持久化层解耦：连接节点负责 WebSocket 生命周期、认证和有界缓冲；投递/队列层负责经认证的密文事件。
- 每个连接、群扇出、历史页、消息大小和未确认队列都有明确上限；达到上限时返回可重试错误或背压，不能无限占用内存。
- 群消息按 groupId 的稳定 hash 路由到分片，但 groupId 不写入日志/指标标签；运维只看分片聚合。
- 在线扇出采用有界并发；慢消费者积压到阈值后断开并要求客户端重连/分页同步，不能拖慢其他成员。
- 离线历史使用稳定游标分页和过期策略；禁止全量扫描、无界 OFFSET 或一次性广播全部历史。
- 每连接限流只是第一道线，前置网关还需连接配额、TLS 握手保护、IP/ASN 自适应策略和 DDoS 缓解。

## 文件设计

- 客户端流式分块加密/上传，不把整个大文件读入内存。
- 上传控制面与对象数据面分离：中继只协商短期能力，分块直接到对象存储。
- 每用户/群/对象存储租户配置字节、对象数、并发上传和未完成上传上限；这些配额基于匿名化/短期能力上下文，避免构建长期行为画像。
- CDN 只缓存密文并受 TTL、撤回、区域和访问令牌策略控制；缓存命中不是读取授权。
- 清理作业可暂停/续跑、幂等、可观察，但不扫描解密文件。

## 目录、公告与推送

- 目录 checkpoint 生成与 proof 查询分离；checkpoint 写入串行可审计，查询使用只读副本/缓存但必须返回可验证 proof。
- 公告以不可变签名对象和 CDN 缓存扩展；发布过程独立限流和审批，不能通过热路径直接改写已发布对象。
- 推送按最小唤醒语义批量发送、指数退避和去重；平台失败/限额不会阻塞消息持久化或中继。
- 任一域不可用时，客户端可使用已验证缓存或稍后同步；不得跳过身份/签名验证换取“可用”。

## 通话容量

- 一对一 P2P 和 TURN 中继分别计量；隐私优先 TURN 模式按带宽规划，而不是被当作免费回退。
- 群 SFU 按 region、会话、编码层和最大订阅数隔离；音频与视频、屏幕共享和录制（若未来允许）各有独立配额。
- 媒体帧 E2EE 会影响 CPU、带宽自适应和关键帧策略，容量测试必须使用真实目标设备而非只测服务端。
- 通话 admission control 在接入前检查区域容量、设备能力、令牌有效期和群成员版本；拒绝时提供明确重试/降级说明，但不降级内容保护。

## 可靠性目标

每个环境为以下指标定义目标、测量窗口、告警和负责人：

- 消息连接成功率、认证成功率、投递确认延迟、历史同步完成率。
- 目录 checkpoint 新鲜度、proof 验证失败率、KeyPackage 可用率。
- 文件完整性成功率、续传成功率、过期清理滞后。
- 公告验签成功率、更新拉取延迟、推送唤醒成功率。
- TURN/SFU 连接成功率、往返时间、丢包/抖动、媒体密钥轮换成功率。
- 更新签名/来源验证成功率和客户端安全版本覆盖率。

这些指标只允许聚合维度：组件、版本、region、时间窗、错误枚举和容量桶；禁止按用户、群、联系人、消息内容或完整 IP 打标签。

## 压测与故障注入

- 用合成凭证、合成密文和合成文件执行负载测试；不得将生产聊天/文件复制到压测环境。
- 覆盖慢消费者、断网重连、突发群扇出、历史分页、文件中断、对象存储限额、目录 proof 峰值、推送故障、TURN/SFU 区域失效。
- 验证背压不会丢失已确认消息、不会生成未界定重试风暴、不会扩大日志数据。
- 每次扩容或协议/加密 Core 变更后重做基准；记录设备端 CPU、电量、内存和弱网体验。
- 灾备演练验证恢复后不会重新接受被吊销设备、旧目录 checkpoint、过期发布物或已经删除的能力令牌。

## 发布门槛

- 每个核心域有容量模型、限额、过载策略、SLO、告警、值班责任和演练记录。
- 负载下仍满足消息完整性、身份验证、游标稳定性和密钥状态安全性；性能优化不得改变安全状态机。
- 公共状态页只发布聚合服务健康，不暴露活跃群、用户地理、设备或攻击目标信息。
