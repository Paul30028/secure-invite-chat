# 安全通信架构 v2

> 本文定义从当前原型迁移到可审计安全通信产品的目标架构。它不是“立即实现清单”，也不代表当前版本已具备本文所述全部安全属性。

## 1. 安全目标与边界

### 保护目标

- 聊天内容、文件内容、通话媒体仅由参与设备解密。
- 服务端只承担认证、投递、密文存储和流量转发，不持有内容密钥。
- 被移除成员不能解密成员变更后的新消息。
- 单个消息密钥或单台设备密钥泄露不应永久暴露所有后续内容。
- 用户可核验设备身份变更；无效签名、重放和身份不匹配内容不能被当作正常消息显示。

### 不能承诺的属性

端到端加密不能自动隐藏 IP、连接时间、流量大小、在线状态或群规模。TURN、SFU、推送服务和网络运营方仍可能看到部分元数据。产品文案不得承诺“完全匿名”或“完全防审查”。

## 2. 密钥层次

```
账号恢复密钥（可选，用户控制）
 └─ 设备
     ├─ 长期签名密钥：身份认证、成员资格和安全码
     ├─ 密钥协商密钥：接收群 epoch 密钥包
     └─ 安全存储包装密钥：保护本地密文状态
         └─ 群组 epoch
             ├─ 消息发送链 / MLS 状态
             ├─ 文件内容密钥包
             └─ 通话媒体密钥
```

- 长期签名密钥与密钥协商密钥必须分离。
- 私钥不可导出；不得写入 `localStorage`、日志、崩溃报告或备份明文。
- 当前 P-256 签名身份用于迁移期；正式协议库选型需统一处理签名、密钥协商、序列化和测试向量。

## 3. 安全存储迁移

定义 `SecureKeyStore` 抽象，不允许业务层直接读写浏览器存储：

| 平台 | 正式存储 | 开发模式 |
| --- | --- | --- |
| Android | Android Keystore + 加密数据库 | 显式本地开发开关 |
| iOS | Keychain（需要时 Secure Enclave）+ 加密数据库 | 显式本地开发开关 |
| Desktop | 系统凭据库或受审计的 Rust 安全存储 | 禁止使用 WebView localStorage |
| Web | 仅受限演示；IndexedDB 保存不可导出 CryptoKey | 不作为高风险通信正式客户端 |

迁移规则：

1. 新版启动时生成新的不可导出设备密钥。
2. 旧版 localStorage 中的群密钥只允许一次性迁移到安全存储。
3. 迁移成功后删除旧私钥、管理员 token 和导出 JWK。
4. 无法安全迁移时，要求用户通过已认证设备重新加入或重新配对。
5. 不提供“静默降级”为明文存储的路径。

## 4. 群组密钥 epoch 与成员变更

当前共享群密钥不能满足移除成员后的保密要求。迁移期采用明确 epoch：

1. 管理操作提出成员变更。
2. 仍在群内的每台设备提供密钥协商公钥。
3. 发送者生成新的随机 `epoch_secret`，为每台剩余设备创建加密的 `KeyEnvelope`。
4. 服务端只投递 `KeyEnvelope`，不能读取 `epoch_secret`。
5. 客户端确认新 epoch 后，只接受该 epoch 的新消息；旧 epoch 仅用于解密历史。
6. 被移除设备不会收到新 key envelope，且其 WebSocket 认证资格被撤销。

迁移期的逐设备密钥分发仅作为过渡。长期群组协议采用 MLS 或经过独立审计的等价实现，以获得成员变更、前向保密和失陷后恢复能力。

## 5. 消息与文件

### 消息

- 每条消息包含：协议版本、群 ID、epoch、发送者设备、单调序号、客户端消息 ID、密文和认证数据。
- 客户端对重复消息、过期 epoch、签名失败和设备身份不匹配消息执行隔离。
- 服务端写入的消息 ID 不替代客户端消息 ID；后者用于幂等和重放检测。

### 文件

- 每个文件生成独立的随机内容密钥。
- 文件按固定大小分块，以 AEAD 加密；每块绑定文件 ID、chunk 序号和 epoch 为附加认证数据。
- 对象存储仅保存密文、密文哈希与过期时间。
- 聊天消息携带经当前群 epoch 加密的文件密钥和密文对象描述符。
- 链接预览默认关闭远端抓取；如开启，必须由客户端明确同意并披露隐私影响。

## 6. 音视频

- 一对一：WebRTC + TURN；信令通过认证后的投递服务。
- 群通话：SFU 只转发编码媒体；在编码帧层再次端到端加密。
- 媒体密钥从当前已认证会话或群 epoch 导出，并在成员变更、重新入会或密钥异常时轮换。
- 不把 SFU 的传输加密误称为端到端媒体加密。

## 7. 首页公众通知

公众通知与私密聊天完全隔离：

- 内容可以公开，但必须由发布者签名。
- 客户端固定或经透明更新机制获得发布者公钥，验签后才显示。
- 推送只发送不透明唤醒或公开通知 ID，不混入私聊内容。
- 公众订阅、行为统计和私聊身份不使用同一标识符。

## 8. 发布门槛

在以下项目完成前，不得将产品描述为 Signal 级安全通信：

- 设备认证强制开启，且无裸 `device_id` 恢复路径。
- 安全存储迁移完成，生产版本不再依赖 localStorage 密钥。
- 成员变更触发新的群 epoch。
- 文件分块加密、重放防护和完整性验证完成。
- 一对一与群组密钥协议经过独立密码学审计。
- 威胁建模、测试向量、渗透测试、依赖审计和签名发布流程通过。
