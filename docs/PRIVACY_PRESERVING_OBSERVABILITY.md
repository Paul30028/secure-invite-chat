# 隐私友好的可观测性与事故响应（设计稿）

> 状态：尚未实现。目标是让团队能发现服务故障、滥用和安全事件，同时不把聊天系统的日志、指标或崩溃报告变成内容/身份监控数据库。

## 数据最小化规则

默认禁止进入任何日志、trace、metric、崩溃报告或分析系统的数据：

- 聊天正文、密文、IV、文件内容、文件名、文件 hash、缩略图、链接 URL 与公告正文。
- 私钥、群 state、Recovery Secret、KeyPackage 私有材料、管理员 token、认证签名、预签名 URL。
- 原始 deviceId、root credential、群 ID、联系人标识、完整 IP、精确 GPS、WebRTC ICE 候选和 SDP。
- 请求/响应原文、HTTP 查询参数、Authorization header、Cookie 与推送 token。

安全默认不是“先收集再脱敏”，而是应用代码从一开始不生成这些字段。脱敏处理器只是第二道防线。

## 可采集的最小信号

| 类别 | 允许的聚合信号 | 禁止关联 |
| --- | --- | --- |
| 中继健康 | 连接数、发送成功/失败数、延迟分位、队列深度、限流数 | 设备/群/消息内容 |
| 目录健康 | checkpoint 生成/验证失败数、proof 类型、延迟 | 被查询的 credential |
| 文件服务 | 上传/下载字节桶、完整性失败数、过期清理数 | 文件名、fileId、对象 URL |
| 公告服务 | 签名验证结果、缓存命中、版本分布 | 阅读者、正文、链接 |
| 通话服务 | TURN/SFU 容量、丢包/抖动聚合、令牌拒绝数 | SDP、ICE、媒体 key、参与者关系 |
| 客户端 | 版本、平台、显式同意后的错误类别 | 聊天/联系人/恢复/设备身份 |

任何分桶指标在样本过小、时间范围过窄或组合后可能重新识别用户时，必须抑制、合并或延迟。

## 事件模型

服务端事件使用 allowlist schema，而不是任意属性：

~~~
RelayEvent {
  eventName: "relay.message_rejected"
  reason: "rate_limited" | "invalid_schema" | "not_authenticated"
  protocolVersion
  deploymentRegion
  aggregateWindow
}
~~~

- eventName、reason 和版本均为有限枚举；未知字段拒绝写入。
- 关联 ID 只能是每进程/每窗口短生命周期随机值，不能跨服务、跨天或跨业务域复用。
- 出现异常时保留计数、时间桶和组件版本，不保留触发消息。
- 客户端诊断默认关闭；用户主动发送诊断包前展示预览，且本地扫描/删除敏感字段。

## 访问、保留与删除

- 运维实时指标采用最小读权限和审计访问；内容团队、公告团队和客服无权读取中继/目录原始事件。
- 原始安全事件保留期应短于聚合健康指标；每类数据定义自动过期任务、所有者和删除验证。
- 生产调试开关、详细网络日志和数据包捕获默认禁用，只能由双人审批在受限时段启用；使用后必须关闭、审计并删除。
- 备份、导出、第三方 APM 与告警通知遵循同一字段禁止列表；不得因“可观测性”绕过数据最小化。
- 用户删除账户/设备不等于立即清除法定/安全审计记录，但保留例外必须公开、最小化、隔离并设到期。

## 告警与处置

高优先级告警聚焦安全边界和可用性，而非用户行为：

- 目录 checkpoint 分叉、签名失败激增、证书/端点异常、密钥轮换失败。
- 认证拒绝/限流突增、协议解析错误峰值、异常版本回滚、依赖/镜像签名验证失败。
- 文件完整性错误、推送 schema 违规、TURN/SFU 令牌重放或服务容量耗尽。
- 发布签名、SBOM、构建来源或部署 policy 验证失败。

告警消息本身只含组件、风险等级、聚合时间窗、部署版本和最小复现线索；不转发请求样本、用户标识或密文。

## 事故响应流程

1. **准备**：明确值班、权限、密钥轮换、证据保全、用户通知和法律联络职责；定期演练。
2. **检测与分级**：用最小化事件判断影响范围；禁止为了调查而扩大常规日志采集。
3. **遏制**：可撤销端点、停用受损发布密钥、禁用特性、限流、隔离服务或吊销凭证。
4. **根除与恢复**：修复、轮换、重建可信产物、验证目录/发布/协议状态，逐步恢复。
5. **通知与复盘**：向用户说明已知影响、版本、缓解措施和剩余风险；发布不含受害者信息的复盘与回归测试。

如果怀疑客户端/发布供应链被攻破，优先停止更新和分发，使用独立可信渠道发布已签名状态公告；不能依赖可能已被攻破的应用内内容作为唯一通知方式。

## 验收门槛

- 静态和动态测试证明禁止字段不会到达日志、trace、metric、错误上报、告警或第三方 SDK。
- 每个 telemetry schema 有字段 allowlist、保留期、数据所有者和访问审计。
- 在注入聊天正文、token、URL、IP、ICE/SDP 和密钥样本后，端到端日志扫描无泄露。
- 完成目录分叉、发布密钥泄露、中继滥用、对象存储暴露和客户端供应链事件的桌面演练。
- 用户隐私说明与实际 telemetry schema、保留策略和第三方处理者保持一致。
